English

Before contacting support

  1. Open Settings and try Restart Backend.
  2. Open Diagnostics and use Copy Summary.
  3. Use Export Logs (.zip) if detailed investigation is needed.
  4. If setup or login is broken, check the onboarding transcript at setup-debug.log.
  5. If the app state is unrecoverable, use Reset App.

Useful details to include

  • ClawApp version and build
  • Bundled OpenClaw version
  • Bundled Node.js version
  • Active provider and selected model
  • Whether debug logging was Off, Metadata Only, or Full Content
  • The exact error text shown in the UI

Support workflow

ClawApp is designed to keep OpenClaw state, logs, and configuration inside the app sandbox. Support should start from the exported diagnostics and logs instead of asking users to inspect arbitrary filesystem locations.

If you email support, include only the minimum information needed to investigate the problem. Do not send API keys or secrets in plain text.

简体中文

联系支持前建议先做这些检查

  1. 打开设置，先尝试重启后端。
  2. 打开诊断，使用复制摘要。
  3. 如果需要更详细排查，使用导出日志 (.zip)。
  4. 如果是引导或登录问题，请检查 setup-debug.log。
  5. 如果应用状态已经不可恢复，再使用重置应用。

建议随工单一起提供的信息

  • ClawApp 版本号和构建号
  • 内置 OpenClaw 版本
  • 内置 Node.js 版本
  • 当前提供商和所选模型
  • 调试日志级别是关闭、仅元数据还是完整内容
  • 界面上显示的准确报错文本

支持流程

ClawApp 会把 OpenClaw 的状态、日志和配置保存在应用沙盒内。支持排查应优先基于应用导出的诊断摘要和日志，而不是要求用户去手动查找任意系统目录。

如果通过电子邮件联系支持，请只发送排查所需的最少信息，不要直接发送 API Key 或其他敏感凭据。
